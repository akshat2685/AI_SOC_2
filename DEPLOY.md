# AI SOC 2 — MVP Deploy Guide

Split deploy: **backend on Render**, **frontend on Vercel**. Do Part 1 first
(you need the backend URL for Part 2).

Prerequisites: this repo pushed to GitHub on branch `mvp-live`.

---

## Part 1 — Backend on Render

### 1.1 Create the Blueprint

1. Go to [dashboard.render.com](https://dashboard.render.com) -> **New** -> **Blueprint**.
2. Connect the `akshat2685/AI_SOC_2` repo, select branch **`mvp-live`**.
3. Render reads `render.yaml` and proposes two resources:
   - Web Service **`aisoc2-backend`** (Docker, `Dockerfile.backend-prod`)
   - PostgreSQL **`aisoc2-db`** (starter plan)
4. Click **Apply**. The build takes a few minutes (Python 3.11 image + pip install).

### 1.2 Environment variables

`render.yaml` already wires the safe ones:

| Variable | Value source | Notes |
|---|---|---|
| `SECRET_KEY` | auto-generated by Render | JWT signing. Keep it secret; backend won't boot without it |
| `AUDIT_SECRET_KEY` | auto-generated by Render | Audit-log signing |
| `POSTGRES_URL` | from `aisoc2-db` | Managed Postgres connection string |
| `BACKEND_CORS_ORIGINS` | **you set this after Part 2** | Your Vercel URL, e.g. `https://aisoc2-frontend.vercel.app` |
| `GEMINI_API_KEY` | **you paste this** | From [Google AI Studio](https://aistudio.google.com/apikey). Without it, AI triage/investigation endpoints stay dark |
| `SOAR_API_KEY` / `SOAR_API_ENDPOINT` | optional | Turn on automated response actions |
| `NEO4J_URI` / `NEO4J_USER` / `NEO4J_PASSWORD` | optional | Neo4j Aura free tier (see 1.4) |
| `QDRANT_URL` / `QDRANT_API_KEY` | optional | Qdrant Cloud free tier: cluster URL + API key |
| `REDIS_URL` | optional | Upstash Redis (used in Phase 5; harmless until then) |
| `LOG_LEVEL` | `INFO` | |

> `KAFKA_BOOTSTRAP_SERVERS` is intentionally **unset** for now (Phase 5):
> the event bus runs in-memory and logs a warning.

### 1.3 Verify

- Open `https://<your-service>.onrender.com/api/v1/health` -> expect `{"status":"ok",...}`.
- Open `https://<your-service>.onrender.com/api/v1/openapi.json` -> the full API surface.
- Copy the backend URL (no trailing slash). You need it for Part 2.

### 1.4 Optional: Neo4j Aura (attack-chain graph, ~5 minutes)

1. Sign up at [neo4j.com/cloud/aura](https://neo4j.com/cloud/aura/) (free tier, no card).
2. Create a **Free** instance -> note the **Bolt URI**, username `neo4j`, and generated password.
3. In Render dashboard -> `aisoc2-backend` -> **Environment**, add:
   - `NEO4J_URI` = the Bolt URI (looks like `neo4j+s://xxxx.databases.neo4j.io`)
   - `NEO4J_PASSWORD` = the generated password
4. Save (service redeploys). Without these vars the graph features degrade
   gracefully; nothing crashes.

## Part 2 — Frontend on Vercel

### 2.1 Import

1. Go to [vercel.com/new](https://vercel.com/new), import `akshat2685/AI_SOC_2`, branch **`mvp-live`**.
2. Set **Root Directory** to `frontend`.
3. Framework preset: **Next.js**. Build command `npm run build` (default).

### 2.2 Environment variable (the only one that matters)

In the Vercel project -> **Settings** -> **Environment Variables**, add:

| Variable | Value |
|---|---|
| `NEXT_PUBLIC_API_URL` | `https://<your-render-service>.onrender.com` (from 1.3, no trailing slash) |

Apply to **Production** (and Preview if you want PR previews). Then **Deploy**.

### 2.3 Finish the loop

1. Copy your Vercel URL, e.g. `https://aisoc2-frontend.vercel.app`.
2. Back in Render -> `aisoc2-backend` -> **Environment**, set
   `BACKEND_CORS_ORIGINS` to that URL (comma-separated if more than one).
3. Save -> Render redeploys (~1 min). The UI can now call the API.

### 2.4 Verify

- Open the Vercel URL: dashboard should load and show stats from the backend
  (`/api/v1/stats` reads the live Postgres).
- Endpoints that need features you haven't configured return **HTTP 501 with
  a plain-English reason** (e.g. AI Copilot chat without `GEMINI_API_KEY`) —
  that is intentional honesty, not a bug.

## Local dev (unchanged)

```bash
cp .env.example .env        # then set SECRET_KEY at minimum
docker compose up --build   # full stack: backend, frontend, postgres, kafka, ...
```

`docker-compose.yml` is local-dev only; the live deploy does not use it.

## What's live vs degraded in this MVP

| Capability | Status | What turns it live |
|---|---|---|
| API + dashboard + Postgres | LIVE after Parts 1-2 | — |
| AI triage / investigation (`POST /api/v1/alerts/{id}/investigate`) | DEGRADED | Set `GEMINI_API_KEY` in Render |
| SOAR auto-response | DEGRADED | Set `SOAR_API_KEY` + `SOAR_API_ENDPOINT` |
| Kafka streaming | DEGRADED (in-memory bus) | Set `KAFKA_BOOTSTRAP_SERVERS` |
| Neo4j attack graph | DEGRADED | Set `NEO4J_URI` (+ password), see 1.4 |
| AI Copilot chat, billing, approvals UI | 501 by design | Not in MVP scope |

No endpoint fakes a "connected" status: `/api/v1/health` reports `ok` for the
API itself; feature availability is per-endpoint and honest.
